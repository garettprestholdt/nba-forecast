# Roadmap

Phases 0–3 are the MVP: get a basic model live early in the 2026–27 season so the public
scorecard covers as much of it as possible. Everything after that is improvement.

## Phase 0: Foundations
- [x] uv project, ruff, pytest, pre-commit, `CLAUDE.md`
- [x] CI on every PR (lint, format, tests); `main` protected so merging requires green CI
- [x] Public GitHub repo; the "one button" flow is branch → PR → CI → Merge

## Phase 1: Historical data
- [x] Backfill every game since 2004-05 from ESPN's scoreboard (one request per game day) into
      the local data directory (outside the repo, never pushed). stats.nba.com was the plan, but
      NBA's servers reject non-browser clients.
- [x] dbt staging + `fct_games` mart with data tests: unique IDs, valid franchises, no ties,
      plausible scores, no team playing twice in a day, exact game counts per season
- [x] Flag unusual seasons and games: 2011-12 lockout, 2012-13 cancelled game, 2019-20 bubble
      (neutral site), 2020-21 72 games, NBA Cup finals, All-Star games, postponed games
- [x] CI runs every dbt model and test on a small fixture of real games

## Phase 2: Elo baseline + honest backtest
- [x] Elo with home-court advantage, margin-of-victory multiplier, between-season regression
      (plus an adaptive home-court option)
- [x] Walk-forward backtest: tune on 2005-06 to 2018-19, report held-out 2020-21 to 2025-26
- [x] Log-loss, Brier score (reliability/resolution), accuracy, calibration vs. baselines
- [x] Finding: [home-court advantage drifted](findings/elo-backtest.md); the adaptive model
      fixes the calibration error and will be the live model

## Phase 3: Daily pipeline (MVP)
- [x] Daily GitHub Actions run: results + schedule (ESPN), odds (The Odds API)
- [x] Resumable Elo state on the `data` branch; daily runs reproduce the batch backtest exactly
- [x] Append predictions with `predicted_at`, ratings date, and code SHA; score finished games
- [x] `nbaf verify` gates every commit: append-only predictions, all made before tip-off,
      no duplicates. A failure means nothing is committed
- [x] `data` branch blocks force-pushes and deletion, so the prediction log can't be rewritten

## Phase 4: Public site
- [x] Static site on GitHub Pages, rebuilt after every daily run and every merge to `main`:
      today's predictions vs. the market, season scorecard, team ratings, backtest and calibration
- [x] Generated by `nbaf site` (Jinja2 + Vega-Lite); no runtime API calls
- [x] Chart palette validated for color-vision deficiency in light and dark mode

## Phase 5: Agent layer
- [x] Daily recap agent: Claude Code (headless, in GitHub Actions) writes the morning recap
      from a facts file in an isolated folder; a fact-checker publishes it to the `data` branch
      only if every number and team matches the facts, otherwise a plain template goes out.
      (Auto-publishing replaced the original "recap as a PR" idea: no daily clicks, and agent
      commits never touch `main` or the contributors list.)
- [x] Failure-triage agent: when the daily run or site deploy fails, Claude Code diagnoses it
      from the logs and a read-only copy of the code; our code files a GitHub issue (or comments
      on the open one). You hand the issue to Claude Code locally for the fix PR, so no bot
      commits and CI runs normally. PRs touching triage run a dry-run drill on a real failure.
- [x] Injury availability agent: for each Day-To-Day player whose team plays, Claude Code reads
      ESPN's injury note and estimates the chance they play (quoting the sentence it relied on;
      quotes are checked against the note). A keyword rule makes the same calls as a baseline,
      and box scores score both the next morning. (The NBA's official PDF rejects scripts, and
      ESPN's injury JSON is already structured, so the LLM works on the free-text notes.)
- [ ] Monthly source-scout agent (evaluates candidate APIs from
      [public-apis](https://github.com/public-apis/public-apis) and proposes an adapter)

## Phase 6: Better model
- [x] Kalman-filter team-strength model (uncertainty, drifting home court, rest and travel) vs.
      Elo, tuned on training seasons: [rest matters; the model family doesn't](findings/kalman-vs-elo.md)
- [x] Optional back-to-back penalty for Elo (+0.0022 log-loss on the holdout, 95% CI excludes 0)
- [ ] Promote Elo + back-to-back to the live model (decision pending)
- [x] Player box-score backfill (every game since 2004-05) with reconciliation tests
      (758k player rows, 28,430 games; stats missing at ESPN for ~13% of 2012-18 games)
- [x] Rebuild the 2012-18 box scores ESPN left blank from play-by-play, validated against games
      that have both: [1,777 of 2,062 rebuilt; counting stats 98.9–99.99% exact](findings/pbp-box-rebuild.md)
- [ ] Hybrid model: team history (Elo, efficiency, four factors) + player layer (player values ×
      projected minutes, missing value, roster continuity), stacked with a regularized
      regression; walk-forward evaluation, including "knows the lineup" vs. realistic versions
- [ ] Test whether players have real individual home/away effects (hierarchical shrinkage)
- [ ] Champion vs. challenger: shadow predictions, promote only on backtest + live wins

## Phase 6.5: Fan-friendly site
